## Reproducing it

```bash
# 1. a servable tree: vite build of the patched source, then
python3 element-call/inject-noise.py <vite-dist>/index.html
#    copy noise/{logic,boot,plotina-dfn,source-link}.js, noise/vendor/* and
#    noise/dfn/v3/{pkg,models}/* into <dist>/noise/, drop config.json next to
#    index.html, and put the iframe page below at <dist>/embed.html

# 2. serve it over HTTPS (self-signed is fine)
node element-call/tests/live/serve_bundle.mjs <dist> 3544 <cert-dir>

# 3. run the harness
BASE_URL=https://localhost:3544/ EVIDENCE_DIR=$PWD/out \
  PLAYWRIGHT_FROM=<element-call-src>/package.json \
  node element-call/tests/live/noise_settings_proof.mjs
```

`embed.html`, the iframe page the embedded half needs:

```html
<!doctype html><html lang="en"><head><meta charset="utf-8"><title>call</title>
<style>html,body{margin:0;height:100%}iframe{border:0;width:100%;height:100%;display:block}</style>
</head><body>
<iframe id="call" allow="camera; microphone; display-capture"></iframe>
<script>
  const room = new URLSearchParams(location.search).get("room");
  document.getElementById("call").src = room ? "/room?roomId=" + encodeURIComponent(room) : "/";
</script>
</body></html>
```

## Two things about the stand, for the next run

- **The room is created through the C-S API, not by the app.** A current Synapse
  defaults new rooms to a version whose IDs carry no server name (Element Call
  0.26.1 rejects those), and it refuses the `createRoom` body Element Call sends
  ("Creator user … must not appear in content.users"). The harness makes the room
  with `room_version: 10` and the power levels from `src/utils/matrix.ts`,
  including `org.matrix.msc3401.call.member` at level 0.
- **Guest registration is off on that homeserver**, so every context registers a
  throwaway account through the app's own registration form. Synapse rate-limits
  registration and login per IP: two runs back to back can hit `429`, wait a
  minute. The room-maker token is cached in `EVIDENCE_DIR/room-maker-token.json`
  so a rerun does not log in again.
- The first join of a headless context sometimes publishes no microphone track
  (the bridge then stays `idle`). The harness toggles the microphone, and if that
  does not help, rejoins once — the run above needed that rejoin, which is why
  the log shows it.
