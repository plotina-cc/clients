# Legacy custom-theme tokens: the 41 undefined custom properties

`bundles/<hash>/theme-{light,dark}-custom.css` are generated by the upstream
Element build from `apps/web/res/themes/light-custom/css/_custom.pcss`: the
legacy Sass theme, remapped through the Compound migration. The migration
dropped a set of custom properties but left every `var()` reference behind, so
each sheet uses **41 custom properties that nothing in the shipped app
declares**. 18 of them are used without a fallback in 101 declarations per
sheet, which makes those declarations
*invalid at computed-value time* — the property falls back to `inherit`/initial
instead of the intended colour. That is the visible bug this document resolves:
unstyled text, missing separators, invisible hover states, a near-white auth
card in the dark theme.

## 38 vs 41

The task says 38. Measured against the pinned stock bundle
(`v1.12.32`, `bundles/81bff4fd060173d686ec`) both numbers are right:

| set | count | what happens |
|---|---|---|
| used and undefined app-wide | **41** | every `var()` of a name no sheet/section declares |
| … of those, **defined** | **38** | declared in our block, values derived from the stock sibling sheet |
| … of those, **dropped** | **3** | `--timeline-background-color`, `--icon-button-color`, `--other-user-pill-bg-color`: every use already carries the exact stock Compound token as its own fallback, so the variable is a dead indirection and is removed instead of redefined |

So the "38 undefined custom properties" of the ticket are the 38 names that get a
definition; the other three known-undefined names lose their `var()` wrapper.
After the pass **no custom property used in a custom sheet is undeclared** — the
audit has no allow-list.

## How each decision was made

Element ships `theme-light.css` / `theme-dark.css` next to the custom sheets in
the same `bundles/<hash>/` directory. They are the same stylesheet compiled
from the *current* (Compound) theme, so for almost every use site the stock
sheet contains **the same selector and the same property** with the value the
custom sheet was supposed to resolve to. The `stock` column below is that
value, counted over every use site in the sheet (top values; the full dump is
reproducible with the snippet in the appendix). Nothing in the block is chosen
by eye: it is either the stock value at the same declaration, stock's own
per-theme literal, or — where stock itself is inconsistent — the majority
value, documented in a comment next to the assignment.

Rules used:

1. **define** — the token is still a meaningful indirection (a colour role)
   and stock resolves the same declaration to a stable Compound token.
   Declared once per sheet, inside the sheet, so it only exists while the
   custom theme is active.
2. **drop** — every use already carries the stock expression as its own
   fallback, and the fallbacks differ per state (`:hover`/`:active`). A single
   definition would flatten them; removing the dead indirection keeps today's
   rendering exactly.
3. **define the hooks with their own fallback** — for the four non-colour names
   (`config.json` font stacks, per-element image height / line clamp) the
   definition is the exact expression their uses already fall back to: inline
   styles still win, nothing renders differently, and the pass leaves no
   undeclared name behind. `--font-family` is defined from that literal stack,
   never from `--cpd-font-family-sans` (which is itself
   `var(--font-family,…)` — that would be a cycle).

waved through: each value is the exact fallback its uses already carry, so the
computed value cannot move, and the inline style Element writes (configured
font, measured image height, per-element clamp) still wins over the sheet. That
keeps the invariant total instead of an allow-list that a future upstream sheet
could silently fall outside.

The `--timeline-background-color-50pct` row deserves one extra sentence, because
it is the only row whose value was chosen for the effect it should have rather
than copied from stock, and the effect is easy to over-claim. The definition
makes the variable resolve to the canvas-derived 90 % colour — in the dark theme
`color(srgb 0.105882 0.113725 0.133333 / 0.9)` — instead of stock's
`hsla(0,0%,96%,.9)` near-white in both sheets. On the login screen of the
shipped build it is nevertheless **invisible**: `.mx_AuthPage_modal` carries an
inline `background: initial` (Element's `_withBlur` variant) in v1.12.32, and an
inline declaration wins over the sheet, so that element's computed
`background-color` is `rgba(0,0,0,0)` before and after the block. The before/
after screenshots do differ inside the auth card (`0.78 %` of pixels, bbox
`(553,190)-(923,446)`), but that is the critical/alert text picking up
`--alert`, not this token. Treat the row as "correct resolution, deferred
paint": it paints wherever a use site is not overridden inline, and the login
card is not such a site.

## What stays undefined

Nothing. All 41 names the sheets use are either defined by the block (38) or
removed together with their now-inlined fallback (3). The audit accepts no
"known undefined" exception:

* a legacy name used bare and undeclared fails the pass (`audit_sheet`);
* a new upstream name used bare and undeclared fails the whole-app audit
  (`audit_webapp`), because it is not in the definitions either;
* a dropped name that comes back anywhere in the app fails as well.

The three dropped names appear nowhere in the output.

## Implementation

* `element-web/webapp_fixes.py` — `patch_theme_css()` rewrites one sheet
  (`LEGACY_TOKEN_VALUES`, `…_DARK`, `LEGACY_TOKEN_DROPPED`),
  `apply_theme_css(root)` patches `bundles/*/theme-{light,dark}-custom.css` and
  then calls `audit_webapp(root)`. Idempotent: the marker-delimited block
  (`/* plotina-theme-tokens … */`) is stripped and re-appended, so re-running on
  a branded tree is byte-stable.
* `element-web/branding.py` (web image) and `element-desktop/branding.py`
  (desktop release) both call `apply_theme_css`; the parity test feeds the same
  CSS through both and compares bytes.
* The block is appended **inside** the sheet's existing `@layer app-web` as
  `body,[class*="cpd-theme-"]{…}`. `body` is where Element puts the
  `cpd-theme-*` class (never `<html>`), and custom-property substitution happens
  at the declaring element, so `--cpd-color-*` resolves per selected theme and
  every descendant inherits the computed value. `:root` would freeze the
  wrong theme (and lose to nothing — it is a different element).
* Nothing is patched per use: the 133 `var(--timeline-text-color)` sites stay
  as they are and now resolve. The previous per-use fallback patch is gone
  (the desktop prepare step asserts it does not come back).
* Failure modes that abort the build: no `bundles/*/theme-*-custom.css`; a
  missing sheet of the pair; none of the legacy tokens left in a sheet
  (upstream restructured it); a dropped token used bare; a legacy token used
  bare and undefined; a sheet without the block markers; a dropped token that
  reappears anywhere in the app.

## Tests

* `element-web/tests/branding_test.py` — block defines every decided token (all
  38, including the four config/per-element hooks); no bare undefined legacy use
  remains; dropped indirections lose the `var()` wrapper but keep their
  fallback; dark overrides differ; **a new upstream-style sheet using an
  undefined variable fails the pass** (`test_new_undefined_variable_fails_the_build`);
  a use with a fallback is allowed; both sheets are byte-identical across
  clients (parity).
* `element-desktop/tests/test_webapp_fixes.py` — same invariants through the
  desktop entry point, plus `prepare-webapp.sh`'s checker and a truncated /
  restructured sheet aborting.
* `element-web/scripts/check-theme-tokens.py` — the same predicate as a CLI,
  run by the Dockerfile **and** by `element-desktop/scripts/prepare-webapp.sh`,
  so the web image and the desktop bundle cannot drift. It fails on any custom
  property used without a fallback that no shipped CSS declares, which is what
  catches a *new* upstream sheet, not just the 41 known names.

## Reproducing the measurement

Against an unbranded webapp root, the audit itself names every custom property
that is used bare and declared nowhere (before the pass: the 41 names above):

```sh
python3 element-web/scripts/check-theme-tokens.py --webapp /app
```

The per-name counts in this document (uses, bare uses, stock value at the same
selector) were measured with a throwaway walker over the same two sheets and
their stock siblings `theme-light.css` / `theme-dark.css`; the counts are
reproducible from the four files alone — `var()` uses per name, and for the
stock column the same selector+property in the stock sheet. The measurement was
taken on the pinned bundle `bundles/81bff4fd060173d686ec/` (element-web
v1.12.32) on 2026-11-10; re-run the audit after every `UPSTREAM_TAG` bump — the
test fails, rather than silently regressing, if the new sheets move.
